## 坐标与真实磁位

渲染转换严格使用 `world = rotationZ(source - product.origin) + [item.x,item.y,item.z]`。所有产品原点都在实际安装面，平台安装面固定 Z=110。20 cm 脚的源模型底端为 Z=-100；显示时可以全场景统一上移 100 mm，装配状态坐标不需要变化。

- P01 向上 32 位；H06 大盖向上 4 位。36 位合起来是 x、y 分别为 10、90、110、190、210、290 的笛卡尔积。中央 90/110 的四位只属于 H06。
- villa 外部底部需要 7 位全部匹配：A01 四位、W01/W02 各一位、G05 一位。白柱从原 A02 拆出，外部磁位 XY 和接触面 Z 均保持不变。内部楼梯、草栏等不作为可自由摆放件。
- G03 的四位只匹配 A02 的阁楼区；G06 的两位只匹配 A02 花圃区。
- LHB 的底部三位为 (10,10)、(10,190)、(190,190)。LHR 屋顶安装面高 85.6；屋顶四磁位可承接方糖小屋或兼容的管道底座。
- SHB 的两位是 (10,90)、(90,10)。SHR 没有顶面磁孔，不能无限向上堆叠。
- 各管道采用 `pipe_interfaces.json` 已变换到世界坐标的底磁和端面。不重复应用该文件的 rotation / translation；接触端面检查法线相反、N/S 异极。

磁铁实体中心与接触面不是同一高度。例如 P01 磁心 Z=107，套餐底磁心 Z=112，但安装面为 Z=110；因此不能让两块实体磁铁的中心完全重合。代码采用来自真实接口的接触平面、孔位 XY 和方向进行匹配。V4 A02 上方六个封闭磁孔磁心变为 Z=197，安装接触面仍为 Z=200；这一深度变化不改变网页吸附规则。

吸附枚举所有孔位平移，要求每个外部底磁都匹配，没有按 100 mm 格子硬取整；20 mm 间距不能被忽略。拖放容错为 42 mm，只有通过孔位、占位和碰撞检测的候选点才能吸附。旋转只支持 90° 步进，原位置不匹配即拒绝，不会偷偷移位。

## 碰撞和父子关系

每个产品使用保守的装配空间盒；L 房用两个盒保持 L 型空缺。平台边缘允许源模型本身已有的最大 6 mm 悬出。盒检测会拒绝一部分理论上可交错的网格组合，这是保守的首版限制，不是精确三角网格布尔碰撞。

对子件避开父套餐总包围盒误报；草栏围合空间并非实心占用。V4 套餐包括后栏 G15、左栏 G16、右栏 G17，主装配盒更新为 `[-5,178.2,110,305,300,238]`。V4 源网格布尔检查确认 G03 相对 villa 转 180° 会与 G15 相交 `1198.719748 mm³`，因此 G03 与 G06 均仅允许相对父套餐 0°。这是相对方向规则：父套餐在四个全局方向上都能携带方向一致的阁楼，不代表全局只能朝 0°。

父组件移动或旋转时，所有后代一起做刚性变换，再验证整个配置。删除父件会级联移除其阁楼、花圃或屋顶方屋。每个组件的 `parentId` 是实际承托组件，`base` 表示平台。

## 搭配编号与本地数据

`encodeConfig` 输出 `HM1.<完整 Base64URL 数据>.<CRC32>`。编码包含目录版本、脚长、平台款式、各部件颜色、所有商品/位置/旋转与父子关系，不依赖服务器查表。CRC32 只用于发现复制错误，不用于鉴权。编号可能比较长，复制完整编号才能复现。

编码前严格验证并规范排序；运行时组件随机 ID、添加顺序、对象属性顺序不影响编号。修改颜色、脚长、平台款式、旋转或位置都会改变配置内容及编号。恢复时先验证版本和校验和，再验证产品、颜色、数量、四脚长度、有限数值、父子依赖、真实磁位与碰撞。单平台最多 48 组商品。新配置保存为 `version: 1, catalogVersion: 3`。本地恢复必须先调用 `migrateAssembly`，编号导入调用 `decodeConfigWithMigration` 并展示返回的 messages，不能直接信任 JSON。

`tests/assembly.test.ts` 使用 Node test runner + tsx，覆盖套餐、源磁位、吸附拒绝、叠层依赖、旋转、孔盖替换、价格以及编号还原/篡改。运行 `npm test`。


### 从目录 2 迁移至 V4

`migrateAssembly(value, sourceCatalogVersion?)` 和 `decodeConfigWithMigration(code)` 都返回 `{ state, messages }`。保留 `decodeConfig(code)` 返回状态的兼容 API；需要向用户解释自动调整时使用带迁移信息的 API。

- 目录 2 编号仍按旧 villa 四色顺序 `[A01,A02,G05,G15]` 解析，不使用八件数组误解旧数据。新增 W01/W02 继承 A02 颜色，G16/G17 继承 G15 颜色。
- 原始本地 JSON 如没有 catalogVersion，仅当存在 villa 且所有 villa 的颜色键恰好是旧四键时才认定为旧数据。已含八件颜色的新数据不会因缺少版本标记被当成旧版修正。空旧搭配可直接验证并补充版本。
- 只修复已知旧版相对父套餐 180° 的阁楼：改为与父套餐方向一致，保留四磁位中心、颜色与父子关系。迁移返回“已按 V4 围栏安全方向调整”的解释。V4 接口 XY 没有变化，因此无需移动磁吸中心。
- 新目录 3 的非法方向、旧版 90° 的非法方向、未知颜色、错位、缺失依赖等仍拒绝。迁移不删除组件、不清空搭配、不修改传入对象。失败由调用方保留原始存档和展示错误，不应覆盖为一个空搭配。
- 迁移成功后持久化带 `catalogVersion: 3` 的状态；再次读取不重复提示或调整。重新编码得到目录 3 的自包含编号。

测试中保留了修改前实际生成的目录 2 编号：包含 20 cm 支撑脚、自定义四色 villa、紫色主平台与反向阁楼。同时验证目录 3 即使 CRC 正确，也不能绕过新围栏方向限制。
