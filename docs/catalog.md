# HamilyMart 商品与装配目录

主要模型来自本机 `unified_complete_8x4_v4` 的 `hardware_complete.json`、`pipe_interfaces.json`、`print_manifest.json`、`L_house_parameters.json`、`small_house_parameters.json` 和 `source/build.py`。圣诞食盆 O01 从同一建模项目的历史版本恢复。网页使用装配坐标 GLB，单位为毫米，原始坐标 Z 朝上。

## 平台状态和装配坐标

当前保存结构为 `version: 1, catalogVersion: 4`。主平台仍使用 `baseInsert`、`baseColors`，新增 `removedCovers`。`extension` 为 null 或 `{ direction, baseInsert, baseColors, removedCovers }`。两个平台共用 `legHeight: 0 | 100 | 200`，因此总保持同高。

`getPlatforms(state)` 返回规范化平台视图。主平台父 ID 为 `base`，原点 (0,0)；第二平台父 ID 为 `base2`，位置只能是 left (-300,0)、right (300,0)、front (0,-300) 或 back (0,300)。每种布局都共享完整的 300 mm 边，不允许任意间隙、重叠或斜接。

模型变换为 `world = rotationZ(source - product.origin) + [item.x,item.y,item.z]`。状态安装面始终为 Z=110；显示统一增加 `legHeight - 100`，所以无腿时平台顶面在 Z=10，10 cm 腿时在 Z=110，20 cm 腿时在 Z=210。脚长变化不改磁吸坐标或子件位置。

`addPlatform / movePlatform / removePlatform / setLegHeight / setCoverRemoved / setPlatformPool` 返回 `ActionResult`：成功有 `ok: true, state`；失败保留原状态并提供 `reason`。移动第二平台时其全部后代一起平移，再校验碰撞；删除第二平台级联删除它的后代。`setCoverRemoved` 只接受 H01–H05，H06 由泳池控制。

## 真实磁吸与自动摆放

- 每个平台 P01 向上 32 位；H06 大盖补充 4 位。36 位为 x、y 分别取 10、90、110、190、210、290 的笛卡尔积。中央 x/y 为 90/110 的四位属于 H06。
- 礼物盒小屋有 7 个外部底磁位置，分别来自 A01 四位、W01/W02 各一位、G05 一位。
- G03 按用户确认调整为 136 mm 宽，四底磁由原来的 146 × 94 mm 改为 120 × 94 mm，真实孔位为 (5,192)、(5,286)、(125,192)、(125,286)，接触面 Z=200。一层可用横向或纵向的 90/210 孔对安装；二层保持左侧 (5,192)/(5,286) 两孔兼容，原帽屋位置不用移动。右移 26 mm 也能匹配二层右侧两孔。模型本体和孔位同时派生更新，不靠缩放渲染或虚构孔位实现。源 pivot 继续使用 (78,239,200)，以兼容旧配置；136 mm 宽的碰撞盒与实际新网格一致。派生网格布尔检查确认原二层位置及右移 26 mm 位置均不与 A02 和三边草栏发生实体干涉；左右磁座相对源件的差集均小于 0.001 mm³，Ø8.2 × 4.2 mm 孔形保持。
- G06 两底磁相距 14 mm，对应二层花圃区。历史 O01 底磁为 (127,124,180)、(141,124,180)，同样相距 14 mm，可替换该位置的花圃，两者不能同时占用。
- LHB 三底磁为 (10,10)、(10,190)、(190,190)，允许其中任意两位匹配。LHR 安装面高 85.6 mm，其四磁位可承接方糖小屋或兼容管道。
- SHB 两位为 (10,90)、(90,10)；SHR 没有顶磁孔，不允许继续向上叠。
- 管道底磁及端面来自 `pipe_interfaces.json` 的世界坐标。端面相遇时要求法线相反、N/S 异极。

磁铁实体中心与接触面高度不同。匹配使用孔位 XY 和真实接触平面；例如 P01 磁心 Z=107，但平台安装面为 Z=110。V4 A02 顶磁虽为封闭孔，安装面仍为 Z=200。

`getPlacements` 穷举每一底磁与每一承托磁孔的对齐平移，至少两个不同底磁与承托孔完全匹配才成立。锚点不固定为第一枚磁铁，避免漏掉后两孔对齐的装法。仍校验承托范围、实体占位、泳池边缘、已占磁孔、管道端面和父件方向限制。保留 42 mm 拖放吸附容差；自由位置不能绕过真实磁孔验证。

`autoPlace(state, productId, preferredPlatformId?)` 同时搜索四个水平朝向和所有合法承托面，优先更多匹配磁孔，再考虑指定平台、已有组件周边及源模型预设位置。选择商品后立即返回完整新配置；无任何位置时返回原状态和“放不下去了”。泳池会依次尝试未放泳池且孔周边空闲的平台，无腿状态则提示先选择支撑脚。

## 碰撞和父子关系

各商品使用保守装配空间盒，L 房用两个盒保留 L 型空缺。平台边缘允许源模型已有的最大 6 mm 悬出。这不是三角网格布尔碰撞，少数可以复杂交错的组合可能被保守拒绝。当前要求每个配件由一个承托面支持，尚未扩展到跨两个平台共同承托。

父套餐整体包围盒不作为对子件的实心障碍，使用已核对的子接口范围和方向限制。原版 G03 相对礼物盒旋转 180° 与 V4 后栏 G15 相交约 1198.72 mm³；缩窄新版仍沿用保守的父件安全方向限制，G03、G06、O01 在礼物盒上只允许相对 0°。该限制仅适用于父商品，不强加到一层平台。父套餐自身可按四种方向整体旋转。

旋转以 90° 步进，优先保持当前 pivot；原位磁孔无法匹配时，在同一父组件、同一高度上尝试最近的真实磁吸位置，不跨平台或跳楼层。源 pivot 不一定是新孔阵中心，因此缩窄帽屋旋转可能伴随 26 mm 等距离的位移。旋转搜索不套用拖拽的 42 mm 容差，否则部分有合法朝向的组件仍无法旋转；始终选同承托面上距离最近的可行位置。父组件移动和旋转携带所有后代一起作刚性变换，最近候选若因后代碰撞失败会继续尝试下一候选；所有候选失败时整个动作回滚。删除父件级联删除阁楼、花圃、食盆或屋顶方屋。平台在 `parentId` 中使用 `base` / `base2`，其他父件使用运行时组件 ID。

## 搭配编号、迁移与验证

新编号为 `HM2.<完整 Base64URL 数据>.<CRC32>`，包含目录版本、脚长、两个平台的方向/泳池/孔盖/颜色、所有商品位置和父子关系。CRC 用于发现复制错误，不用于鉴权。所有数据都在编号中，不依赖服务器查表。

编码前严格校验、按两平台依次对父子树规范排序；运行时 ID、添加顺序和对象属性顺序不影响编号。平台方向、盖子移除、配色、脚长、泳池、位置、朝向改变都会更新编号。旧 HM1 目录 2 和目录 3 仍可导入。本轮目录 4 还未发布，因此增加装饰色槽仍保留目录版本 4：HM2 的 villa 颜色数组追加丝带和蝴蝶结两个索引，八个实体部件索引顺序保持不变。导入本轮早先生成的八色 HM2 或八色本地状态时自动补充两个默认黄色槽；新十色数组完整保存独立选择。旧 HM1 仍按四/八实体色解析后补默认槽。

`migrateAssembly(value, sourceCatalogVersion?)` 与 `decodeConfigWithMigration(code)` 返回 `{ state, messages }`；UI 展示迁移消息。本地恢复先迁移后校验；失败保留原始存档，不能用空配置覆盖。`decodeConfig` 保留只返回 state 的便利 API。

- 目录 2 villa 四色 `[A01,A02,G05,G15]` 迁移为八部件：W01/W02 继承 A02，G16/G17 继承 G15。只对已知相对父套餐 180° 的旧阁楼修正为 0°，保留装配位置和颜色，并解释围栏安全调整。
- 无版本本地 JSON 只有在 villa 颜色键恰好是旧四键时才按目录 2 处理；八色结构不会因缺版本标记被自动修方向。
- 目录 3 仅补充无第二平台、未移除盖子的默认字段，已有颜色、位置和泳池保持。非法方向仍拒绝。
- G03 缩窄时保留旧 pivot 和二层左孔：旧 HM1 和本轮原尺寸 HM2 的帽屋位置、颜色、父件均保持，匹配数由四变为二，不需要额外位置迁移。
- 当前目录 4 不修复非法位置、非法朝向或无腿泳池。缺失依赖、循环依赖、重复 ID、未知商品/颜色、非有限坐标均拒绝。最多两平台，每个平台额度 48 组，双平台合计最多 96 组。
