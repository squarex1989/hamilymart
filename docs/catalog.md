# HamilyMart 商品与装配目录

主要模型来自本机 `unified_complete_steel_v9` 的 `hardware_complete.json`、`pipe_interfaces.json`、`print_manifest.json`、`L_house_parameters.json`、`small_house_parameters.json` 和 `source/build.py`。圣诞食盆 O01 直接采用该正式源中的单磁铁版本。网页使用装配坐标 GLB，单位为毫米，原始坐标 Z 朝上。

当前目录使用 Steel V9 中的 43 个零件、50 个颜色体。完整源有 44 个零件、51 个颜色体，另保留尚未上架的 LT2NT 管体。房屋顶盖、礼物盒楼梯及草栏、管道底座仍不可拆售。四腿作为整体切换，也可全部取消；移除的小圆盖不出现在配件清单中，平台价格不变。

泳池在选配目录中单独展示、单独计价，但保存为所属平台的 `baseInsert: "pool"`，不能作为磁吸商品加入 `items`。它占据平台的大圆孔、替换 H06，并自动移除 H06 的四枚磁位。任意平台带泳池时，两个平台均不能切换为无腿。移除泳池会恢复大圆盖。

颜色在 `COLORS` 定义。`baseColors` 使用 P01、H01–H06、B01 和 legs；同一平台四腿共用 legs，两个平台颜色独立。组件 `colors` 以源 group ID 为键，每个套餐部位可单独改色。四种原色仍全部提供：雪白 `#F1EADB`、松绿 `#174A3A`、圣诞红 `#B8273C`、金色 `#C99B46`。礼物盒蝴蝶结已替换为五角星，丝带和五角星均默认金黄色 `butter`，可以独立改色。

`getSourceColorSlot(groupId, sourcePart?, colorKey?)` 优先按 `SOURCE_COMPONENT_COLOR_SLOTS` 查源颜色体 ID：A01_Gold 对应 `A01-ribbon`，A01_ChristmasRed 对应 `A01-bow`；兼容旧 A01_BowGold、A01_StarGold。V9 星星源色为红色，网页默认金黄色沿用用户要求；丝带、星星仍使用独立颜色槽。没有组件 ID 映射时，才回退 `SOURCE_PART_COLOR_SLOTS` 的旧 colorKey 映射（Gold → ribbon、ChristmasRed → bow）。网页渲染和缩略图共用此函数。

`COLOR_SLOTS` 定义名称及默认色；五角星保留历史内部 key `A01-bow`，只将显示名称改为“五角星”。`getColorParts(parts)` / `getProductColorParts(productId)` 仍在八个实体部件后追加丝带、五角星两个配色槽，顺序和总数保持不变，`getDefaultColors` 返回这十个颜色键。两个虚拟槽是实体上的配色区域，不增加零件数量或价格。清单 colors 包含它们；parts 保持八件，丝带或五角星颜色不同的套餐分行统计。

## 平台状态和装配坐标

当前保存结构为 `version: 1, catalogVersion: 5`。主平台仍使用 `baseInsert`、`baseColors`，新增 `removedCovers`。`extension` 为 null 或 `{ direction, baseInsert, baseColors, removedCovers }`。两个平台共用 `legHeight: 0 | 100 | 200`，因此总保持同高。

`getPlatforms(state)` 返回规范化平台视图。主平台父 ID 为 `base`，原点 (0,0)；第二平台父 ID 为 `base2`，位置只能是 left (-300,0)、right (300,0)、front (0,-300) 或 back (0,300)。每种布局都共享完整的 300 mm 边，不允许任意间隙、重叠或斜接。

模型变换为 `world = rotationZ(source - product.origin) + [item.x,item.y,item.z]`。状态安装面始终为 Z=110；显示统一增加 `legHeight - 100`，所以无腿时平台顶面在 Z=10，10 cm 腿时在 Z=110，20 cm 腿时在 Z=210。脚长变化不改磁吸坐标或子件位置。

`addPlatform / movePlatform / removePlatform / setLegHeight / setCoverRemoved / setPlatformPool` 返回 `ActionResult`：成功有 `ok: true, state`；失败保留原状态并提供 `reason`。移动第二平台时其全部后代一起平移，再校验碰撞；删除第二平台级联删除它的后代。`setCoverRemoved` 只接受 H01–H05，H06 由泳池控制。

## 真实磁吸与自动摆放

- 每个平台 P01 向上 32 位；H06 大盖补充 4 位。36 位为 x、y 分别取 10、90、110、190、210、290 的笛卡尔积。中央 x/y 为 90/110 的四位属于 H06。
- 礼物盒小屋有 7 个外部底磁位置，分别来自 A01 四位、W01/W02 各一位、G05 一位。
- G03 同步 V9 的 162 mm 宽版本，四底孔为 (5,192)、(5,286)、(151,192)、(151,286)，接触面 Z=200，孔距 146×94 mm。二层 A02 四位对应；一层无相应两孔组合，不能再直接放置。业务 pivot 仍为 (78,239,200)，碰撞盒覆盖完整 162 mm 宽度。
- G06 与 O01 各一个底磁位，接触点均为 (285.5,264,200)，对应 A02 共享钢片位。仅这两个商品声明单点磁吸；两者不能同时占用同一位置。食盆 origin 更新为 (285.5,264,200)，源 bounds 为 [246,236,200,301,296,221]。
- LHB 三底磁为 (10,10)、(10,190)、(190,190)，允许其中任意两位匹配。LHR 安装面高 85.6 mm，其四磁位可承接方糖小屋或兼容管道。
- SHB 两位为 (10,90)、(90,10)；SHR 没有顶磁孔，不允许继续向上叠。
- 六种管道支撑 ST1B/ST2B/ST3B/LT1B/LT2B/LT3B 已取消共十二个侧面磁孔，十二个底部磁孔保持原坐标与规格。底磁和端面几何沿用 `pipe_interfaces.json` 的世界坐标；端面不再含磁极属性，相遇时只要求法线相反。底部双孔匹配、实体碰撞及磁位占用校验保持。

V9 平台接收件是钢片，配件是磁铁；五金实体中心与接触面高度不同。匹配使用孔位 XY 和真实接触平面，P01 安装面仍为 Z=110，A02 主安装面仍为 Z=200。接收槽封面变化不改变这些装配高度。

`getPlacements` 穷举每一底磁与每一承托磁孔的对齐平移，按照商品声明的最少接触点数匹配：默认至少两个，花圃与食盆至少一个。锚点不固定为第一枚磁铁，避免漏掉后两孔对齐的装法。仍校验承托范围、实体占位、泳池边缘、已占磁孔、管道端面和父件方向限制。保留 42 mm 拖放吸附容差；自由位置不能绕过真实磁孔验证。

`autoPlace(state, productId, preferredPlatformId?)` 同时搜索四个水平朝向和所有合法承托面，优先更多匹配磁孔，再考虑指定平台、已有组件周边及源模型预设位置。选择商品后立即返回完整新配置；无任何位置时返回原状态和“放不下去了”。泳池会依次尝试未放泳池且孔周边空闲的平台，无腿状态则提示先选择支撑脚。

## 碰撞和父子关系

各商品使用保守装配空间盒，L 房用两个盒保留 L 型空缺。平台边缘允许源模型已有的最大 6 mm 悬出。这不是三角网格布尔碰撞，少数可以复杂交错的组合可能被保守拒绝。当前要求每个配件由一个承托面支持，尚未扩展到跨两个平台共同承托。

父套餐整体包围盒不作为对子件的实心障碍，使用已核对的子接口范围和方向限制。V9 沿用经模型核对的保守父件安全方向限制，G03、G06、O01 在礼物盒上只允许相对 0°。该限制仅适用于父商品，不强加到一层平台。父套餐自身可按四种方向整体旋转。

旋转以 90° 步进，优先保持当前 pivot；原位磁孔无法匹配时，在同一父组件、同一高度上尝试最近的真实磁吸位置，不跨平台或跳楼层。源 pivot 不一定是孔阵中心，因此旋转可能伴随位置调整。旋转搜索不套用拖拽的 42 mm 容差，否则部分有合法朝向的组件仍无法旋转；始终选同承托面上距离最近的可行位置。父组件移动和旋转携带所有后代一起作刚性变换，最近候选若因后代碰撞失败会继续尝试下一候选；所有候选失败时整个动作回滚。删除父件级联删除阁楼、花圃、食盆或屋顶方屋。平台在 `parentId` 中使用 `base` / `base2`，其他父件使用运行时组件 ID。

## 搭配编号、迁移与验证

新编号仍为 `HM2.<完整 Base64URL 数据>.<CRC32>`，目录版本升级为 5，包含脚长、两平台方向/泳池/孔盖/配色、组件位置和父子关系。CRC 发现复制错误，不用于鉴权；编号自包含，不依赖服务器查表。编码前严格校验，并对两平台的父子树规范排序，运行时 ID 与添加顺序不影响编号。

保留旧 HM1 目录 2/3、HM2 目录 4 和本地存档的迁移入口。实体零件索引及颜色槽顺序保持；五角星仍使用 `A01-bow`，八色旧套餐会补上独立丝带与星星默认色。旧目录 2 四件套餐的白柱继承二层配色，左右草栏继承原草栏配色。

`migrateAssembly(value, sourceCatalogVersion?)` 与 `decodeConfigWithMigration(code)` 返回 `{ state, messages }`，界面显示迁移说明。V9 改变帽屋宽度及花圃/食盆接口，旧配置需重新验证真实安装位置；无法合法恢复时给出明确错误，保留原始本地存档，不静默删除配件或用空平台覆盖。当前目录 5 的新配置严格校验，不自动修复非法坐标或朝向。

迁移先按对应旧目录的几何规则验证，非法旧配置不会借升级修复。旧食盆的源网格与 origin 同步平移，因此世界位置保持；花圃也保持原位。仍然合法的二层帽屋优先保留，旧偏右帽屋移到同一父套餐的最近合法磁位；旧一层帽屋只尝试已有礼物盒的空闲二层，优先同一平台，不新增小屋。每次位置调整均显示原因；没有位置则拒绝恢复，原配置不变。

缺失父件、循环依赖、重复 ID、未知商品/颜色、非有限坐标均拒绝。最多两平台，每个平台额度 48 组，双平台合计最多 96 组。
